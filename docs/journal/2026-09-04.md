# 2026-09-04 — One vocabulary, a studio that switches, and a table to argue with it in

Four commits on `feat/semantic-token-vocabulary`, each one uncovering the next.
The layer had two sets of names, so it got one; having one made it worth
looking at in both modes, so the studio learned to switch; switching showed
there was nowhere to edit the values, so the Semantics tab became a table; and
the table's own page turned out to hold a second thing called a theme.

## What was done

**The studio's chrome and the workspace's export had grown separate names for
the same roles.** `--color-bg-surface` in one, `--color-surface-raised` in the
other, and `-base` suffixes where the first had to dodge Astryx. They share one
set now — `fg.*`, `surface.*`, `border.*`, `action.*`, `status.*`, `focus.ring`
— with `theme.css` defining them for the studio from a neutral ramp that has to
render before any palette exists, and the workspace exporting the same names
for a client. A developer reads one name whether they are looking at the studio
or at the file it produced.

**The names dodge Astryx, and that was measured rather than assumed.** Astryx
defines `--color-border`, `--color-accent`, `--color-on-accent`,
`--color-skeleton` and every `text-*` and `background-*` inside its own theme
layer, scoped to the theme element. Our `@theme` block lands in Tailwind's
lower layer at `:root`, so a token of ours with one of those exact names loses,
and the bridge line meant to re-assert it collapses into
`--color-border: var(--color-border)`. Hence no bare `border`, `strong` rather
than `emphasized`, `action` rather than `accent`. The bridge test reads the
resolved variable on the element Astryx scopes to and compares it with ours.

**`text` became `fg`, and seven roles were added.** The same token colours
icons and rules, so "text" named one use of it. `migrateSemanticIds` follows a
chain — `neutral.dark` to `text.primary` to `fg.primary` — so a layer saved
under the very first names still lands somewhere the seed set has. The new
roles are `action.hover`, `action.active`, `surface.subtle`, `surface.overlay`,
`border.subtle`, `border.muted` and `fg.disabled`, and `fillSeedRoles` appends
whatever a stored layer lacks, seeded against that project's own palette. It
never touches an empty layer, because an empty layer somebody stored is a
deliberate act. Nineteen tokens where there were twelve.

**Hover and active are states, not signals.** Deriving the accessibility
report's pairs from every `action` and `status` token would have paired
`action.hover` against `status.info` — a row measuring something nobody ever
sees. `semanticPairIds` keeps the two states out of the grid, and the surface
checks still cover the foregrounds on them. Fifteen pairs, as before.

**The studio switches theme, and the switch goes through the provider.**
`ThemeProvider` holds the mode, persists it under `blueprint.colour-mode.v1`,
and hands it to Astryx's `Theme`, which is the only thing that can flip the
chrome. `layout.tsx` no longer pins `data-theme="dark"`; a `beforeInteractive`
script applies the saved mode before first paint, so a reload does not flash
the system scheme for a frame.

**237 primitive references across five CSS modules, and 17 in components,
became roles.** Property-aware rather than find-and-replace: `neutral-800` was
a canvas background in 18 places and a divider border in 24, and those are
different roles. The mapping went by what a rule does — a `border` at 750 is
`border-strong`, a `background` at 750 is `surface-overlay` — and by the
chrome's existing lightness, so the studio still looks as it did. The canvas
sits at 800, panels a step darker at 900, cards between at 850: recessed rather
than lifted, a choice the studio had already made, and the sweep's job was to
name it rather than redesign it. What stayed a primitive stayed for a reason
the guard now knows by file and by value — thumbs that must read on any hue, a
picker plane that is black-to-white by definition, a hue slider that is a
rainbow, a track's source colour, which is data.

**The Semantics tab is a table.** Nineteen names down the side, both modes
across, a decision in every cell, grouped by the part of the id before the dot
the way the export groups them. The list of cards it replaced put each token's
two modes on separate rows, so comparing light with dark — the thing actually
being decided — meant reading diagonally. It reads `useWorkspaceStore` rather
than a private copy: `PaletteStudio` used to read the slice once on load and
write it back from its own state, and now writes through `update`, so the
preview tab and the export read the layer the table just changed.

**The preview page has one theme control, and it is the studio's.** It began
the day with two — the studio's three-state theme beside the page's own
two-state "Colour mode", each flipping a different half of the page. Removing
the studio's left the preview unable to say `system` when every other page
could, and left a studio set to dark opening a light preview. The two questions
are genuinely different, and answering them separately produced exactly that,
so they are one choice now. `ThemeMode` is what was chosen and `ColourMode` is
what gets drawn, with `resolveThemeMode` the only crossing between them.

## What was learned

**A name that reads fine in isolation can still lose a cascade fight.** The
collision with Astryx is invisible in the source: both files say
`--color-border`, both look correct, and the bridge silently resolves to
itself. Nothing errors, nothing warns, and the studio just renders the wrong
colour. The rule that came out of it — read the resolved value on the element
the other library scopes to, not the value you wrote — is the same discipline
that settled the Selector margin two days ago, arriving by a different door.

**What governs the mode is a class, not an attribute.** Flipping
`html[data-theme]` does flip `color-scheme` on the theme host and every token
read there, which is what made it convincing; the studio's controls stay dark
anyway, because `<Theme mode>` renders an inner element carrying a StyleX class
that React chooses from the prop. Only `setMode` moves it. Found by
screenshotting light mode and seeing dark — the fix was already scaffolded in a
provider nobody had wired up.

**A border token equal to the surface beneath it is not a border.** The table's
grid dividers were invisible because the retune had put `border-default` at
800, the canvas's own value. Both measured on the cell at oklch(0.2). A palette
of roles makes it very easy to give two roles the same value and never see it
until something needs the difference.

**Correctness has a per-keystroke price, and the drag test collects it.**
Retiring legacy storage keys on every write re-parsed the whole workspace, and
the typography keyboard drag stalled under it — measured across sixteen runs
each way. Doing it only on the write that creates the workspace key costs one
`getItem`. The failing persistence tests that started this had a subtler
lesson: the keys had been retired all along by whichever load happened to
follow the first write, and that load turned out to be the palette studio
writing its semantics slice on mount. Moving that write onto the store removed
the load, and the cleanup that was never anybody's job stopped happening.

**Two right answers can still make a wrong studio.** Keeping the preview's mode
separate was argued carefully and written down: the mode a client's system is
demonstrated in is not the mode the viewer prefers for their own screen. It is
true, and the result was a person choosing dark and getting it on three pages
out of four. The distinction survives where it belongs — in the types, so
`system` cannot reach a token lookup that has no half filed under it — and not
as a second control.

**A test can pin the wrong page.** The test that had enforced two controls on
the preview was passing against an unseeded page, which renders no controls at
all. It asserted a count of zero for one of them and got it for the honest
reason and the dishonest one at once. Every replacement here seeds first, and
each new assertion was watched failing before it was trusted: the semantic
migration, the first-write key retirement, and the `system` resolution were
each broken on purpose once.

**The keyboard-drag test is marginal, and it is not this branch's.**
"Reordering groups" shares a `carryDown` helper across three tests, and the
full suite failed a different one of them today than it did yesterday — the
race lands on whichever test loses it. Run alone against `main` at 6247e76,
with none of this work applied, it failed three runs in four. It was left
exactly as it is; it deserves its own branch and a real look at the readiness
signal it polls.
