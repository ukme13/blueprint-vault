# 2026-09-02 — A menu placed twice, a patch release that broke a field, and a formatter that had never seen half the repo

## What was done

**`pnpm format` had never formatted the repository.** The glob was
`**/*.{ts,tsx,md}`, so CSS modules, configs, package manifests and the
workspace yaml were outside the command that claims to format everything. It
now runs over the whole tree with `--ignore-unknown`, which picks up whatever
file type gets added next without another glob edit. Thirteen files were
genuinely out of shape, `system.ts` and `RoleGroupEditor.tsx` among them.

**The hundred-file diff was line endings, and it would have made the hook
unusable.** Git stores LF and, with `core.autocrlf` on, hands Windows checkouts
CRLF back. Prettier's `endOfLine` default is `lf`, so it rewrote every file it
opened. Harmless while nothing checked — but a pre-commit hook reads the
working tree, so on a fresh clone every file would have failed and every commit
would have been refused. A `.gitattributes` pinning the working tree to LF is
what makes Git and Prettier agree.

**`.githooks/pre-commit` checks rather than rewrites**, and `prepare` points
`core.hooksPath` at it on install so there is no new dependency and nothing to
wire up by hand.

**The Selector menu was being placed twice.** Astryx writes both a CSS anchor
position — `position-anchor`, `position-area`, `position-try-fallbacks` — and a
JS-measured `margin-block-start`, inline, on the same popover. The margin is
the fallback for browsers with no anchor positioning. Where a browser has both,
both apply: the margin moves a menu that anchor positioning has already placed.
The script picker, anchored near the bottom of the inspector, opened at the top
of the window on `margin-block-start: -391px` against an anchor at y=365.

The override in `globals.css` neutralises the margin, guarded on
`@supports (position-area: block-end)` so Safari and Firefox keep the fallback
that is still doing the whole job there.

**Astryx is pinned to an exact `0.5.0`.** 0.5.2 does not fix the positioning,
and it breaks `NumberInput`: a typed `1.25` does not take, so the line-height
field cannot be given a unitless ratio.

## What was learned

**Measure which components are affected before writing the rule that fixes
them.** The obvious override was `[popover] { margin-block-start: 0 !important }`.
Measuring first showed the script Selector at `-391px`, the ratio Selector at
`-69px` — and the font Typeahead at no margin at all, landing correctly under
its field. A blanket rule would have "fixed" a component that was never broken,
and the only way to find that out was to open all three and read the numbers.

**A patch release is not automatically safe, and the suite is what says so.**
`^0.5.0` meant the lockfile was the only thing keeping 0.5.2 out. The A/B was
one production build, one machine, one dependency changed: 197/197 on 0.5.0,
196/197 on 0.5.2, and the one difference was a real user-facing break. The
existing line-height test caught it without anyone thinking to look — which is
the argument for pinning rather than trusting the range.

**`aria-expanded` is not the popover's state.** Light dismiss is the browser
closing the element directly, so React has not re-rendered and the attribute
still says expanded on the very click that shut it. Reading it produced a fix
that worked on every _other_ click — a clean alternating pattern that would
have shipped if it had not been instrumented. `:popover-open` is the real
state, and even then the component's own React state has to be settled with a
blur before its focus handler will reopen anything.

**The cheap workaround was the right one.** Swizzling the Typeahead to fix the
click behaviour would have copied 1,882 lines that style themselves with
`stylex.create`, into a workspace with no StyleX compiler — unstyled, with no
error — and the CLI's suggested Babel route disables SWC and breaks
`next/font`, which the app uses. Thirty lines in `GoogleFontPicker` did the
same job. Reading what a tool actually copies, before running it, is cheaper
than the branch that follows running it.
