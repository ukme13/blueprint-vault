# 2026-09-09 — Table follow-ups, shade rails, and a preview that was still in the studio's theme

Work on top of merged stage 5 (`feat/semantic-table-alpha`, PR #111). Three
surfaces, one studio: the Semantics table, the shade-generator lightness
sliders, and the colour Preview tab.

## Semantics table

**Row drag is a body drag, not a handle drag.** dnd-kit core 6.3.1 and
sortable 10.0.0, with a 16px activation distance so a click still selects.
Listeners live on the `<tr>`; a custom pointer sensor ignores chips, inputs
and menus inside the row. The row itself takes no `transform` — transforming a
table row is invalid HTML and breaks the table — and the moving row is a
`DragOverlay`. A drop gap opens while the pointer is over a sibling.

`reorderToken` now takes the current selection. Dragging a selected row moves
the selected block in layer order; dragging an unselected row moves only that
row. Mixed-group selections are a no-op: a drag is not a rename.

**Invented Action and Status names were locked for no reason.** `usedBy`
treated every `isSignallingRole` id as load-bearing for the colour-vision pair
grid. The grid measures signalling roles that already exist; it does not read
a name. Creating `action.token` (no hyphen) inherited "Colour-vision pair
grid" and refused delete. The pair-grid consumer is now only added when
`PREVIEW.has(id)` — seeded `status.success` stays locked, a name somebody
just typed does not.

**New group left the field under search.** `…` → Move to group → New group
opens `SemanticNewGroupDialog` (Astryx Dialog `purpose="form"`). The sidebar
New group control is still the inline field, because that one is creating an
empty folder rather than moving a selection.

**Delete, move, duplicate and paste toast with Undo.** `describeSemanticEdit`
is the sentence; refusals still use `describeRefusals`. The toast's Undo
calls `semanticsHistory.undo`. `uniqueID: "semantic-edit"` so a second delete
replaces the first, and it stays until dismissed while Undo is available —
five seconds is not long enough to notice a row has gone.

**A refused edit must not look like an edit.** Delete and move that change
nothing now return the same layer object. The first version allocated a new
array, recorded a history step, and offered Undo of a no-op.

The table's sensor setup, overlay id and drop slot live in
`useSemanticTableSort`. `use-semantic-actions` is `.tsx` again so the Undo
control is JSX.

## Shade generator

The lightness sliders were Astryx's default fill, which does not say which way
is darker. Each rail is now a black-to-white gradient (`oklch(0% 0 0)` to
`oklch(100% 0 0)`), the filled overlay is hidden, and the thumb fill is the
current lightness. A 1px `border-strong` keeps both ends readable on the
panel. Corners are 4px. Every rail is 14px — first and last were that size
already, and the thin middle rails were the ones being edited.

`linear-gradient(to inline-end, …)` is invalid here. Chromium dropped the
whole declaration and the computed `background-image` was `none`. `to right`
is what actually paints.

## Colour preview

The Text hierarchy chip was Astryx `variant="purple"`. The palette preview is
light-only (`previewShadesFor` says so) and the studio was dark, so the badge
followed chrome tokens onto a light mock. It now paints from
`action.primary-surface` and `action.primary-fg`, with `color-scheme: light`
on the mock so leftover Astryx internals do not invert.

Account balance and Suggested action captions were `fg.primary` at
`opacity: 0.65`. Opacity is not a colour. They use `fg.secondary` at full
strength.

## Lessons

**A consumer list is a claim about a name, not about a category.** "This id
is a signalling role" is true of `action.token`. "The pair grid reads this
id" is not. The lock has to ask the second question. Moving the pair-grid
push inside `PREVIEW.has(id)` was a one-line change; the wrong line had been
making every invented Action name undeletable.

**Returning a new empty-looking layer is not a no-op.** History, toasts and
Undo all key off object identity (`result.layer === before`). Allocating a
fresh array that happens to hold the same tokens records a step you cannot
explain. The early return has to be the same object.

**A CSS gradient that the browser cannot parse fails as "none", not as a
fallback direction.** `to inline-end` looked like the RTL-correct choice.
The test that asked for `linear-gradient` in computed style is what caught
it; the track still had its Astryx class and a visible grey rail.

**A component inside a mock follows the document, not the mock.** Hex on the
heading and body hid the fault. The Badge did not, because its colours are
`light-dark()` tokens against `color-scheme`. The preview's own comment
already said the mode toggle belongs to the system page. The chip had not
read it.

**Fading text with opacity spends contrast you already measured.** Supporting
text is a role with a ratio. 0.65 of `fg.primary` is a different colour that
no check names. The captions now use the role the report already measures as
"Supporting text".
