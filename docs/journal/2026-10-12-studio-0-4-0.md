# 2026-10-12 — Studio 0.4.0, and the guides catch up

One commit on `chore/bump-v0.4.0-and-docs`. The studio is 0.4.0. The changelog says
what is in it, and the guides now describe the two things that grew most since the
last entry: the Accessibility sandbox and the Preview inspector.

## Key changes

- **The version.** `apps/playground/package.json` goes to `0.4.0`. The changelog's
  own test reads that file and fails when the newest entry says anything else, so
  the two moved together.
- **A 0.4.0 entry in What's new**, dated 2026-10-12 on schema v8 (the workspace file
  format did not change). Thirteen items, in three runs: the sandbox and the APCA
  engine, the Preview inspector, and the token and layout changes under them (static
  white and black, the WCAG 2 AA threshold, preset layout bindings and `inset-nav-y`).
- **The Accessibility guide** opens with the sandbox: selecting a layer, the two
  colour sources and the control bar, the score and the WCAG 2 | WCAG 3 toggle, and
  how the studio chooses a text colour (APCA, with the 4.5:1 and Lc 60 lines and the
  3:1 floor).
- **A Preview guide**, `/studio/guides/preview`: selecting, what each kind of element
  offers, strokes and effects, and dressing a button. It is in the internal route
  list, so the nav, the footer and the route test all see it, and Getting started
  names the inspector.

## Architectural decisions

- **Guides are content modules behind a thin page.** The new guide follows the
  existing ones: prose in `content/guides/`, a page that only frames it, one row in
  `INTERNAL_DOCS_ROUTES`. The route test fails on a route with no page and a page
  with no route, which is how it was checked.
- **Studio pages stay out of a handover.** The guide lives under `/studio`, which the
  archive guard already excludes; nothing about it needed a new rule.
- **The changelog states what the code does, not what it was meant to.** Where a
  brief and the code disagreed, the code won (see below).

## Lessons learned

- **A summary written from memory is a list of claims to check.** Two did not hold.
  The Hug / Fill size tags (`320 × 104 · Fill × Hug`) are the sandbox's; the
  inspector's selection shows its size only. And the sandbox does not show unrounded
  scores: an Lc is judged as the whole number it shows, and a ratio is cut to its
  places, so the figure on screen is the figure judged. The changelog says so.
- **A feature with no guide is easy to miss.** The Preview had a paragraph in Getting
  started and nothing else; the inspector is large enough to need its own page, and
  adding one was a route, a page and a content module.
- **Read the version where the test reads it.** `changelog.test.ts` reads the
  playground's `package.json`; bumping any other `version` field would have left the
  test, and the entry's badge, wrong.
