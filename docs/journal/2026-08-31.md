# 2026-08-31 — Semantic colour tokens, end to end

## What was done

**The semantic layer, all five stages.** A layer of names over the primitive
palette: `action.primary`, `surface.base`, `text.primary`, each holding one
reference per mode. The model and resolution, workspace version 2 and its
migration, an editor, a `/preview` page built only from the layer, and the
export and accessibility report moving onto it.
[semantic-tokens.md](../roadmap/semantic-tokens.md) has the stage notes.

Plus a fix to the shade popover, whose swatch simulated colour-vision while the
contrast sample beside it did not, and the icon guidelines in `CLAUDE.md`.

**Planned spacing, radius and elevation** — [scale-studio.md](../roadmap/scale-studio.md).

## What was learned

**Read the code before writing the plan, twice over.** Stage 1 was going to
invent a semantic layer. `preview-assessment.ts` already had one:
`PreviewShades` is eleven semantic roles, hard-coded in a preview helper,
uneditable and never exported. The work was making the existing one explicit,
not designing a new one — and those eleven were the honest seed set, because
they are what the workspace had actually needed.

The same pass killed the next plan too. Spacing was going to reuse
`generateTypeSteps`, and every spacing scale in real use is a linear base unit
rather than a ratio: 1.25 from 4px gives 6.25px, which nobody lays out a page
on. Astryx's radius tokens turned out to be use-named already, which is the
shape the colour layer took four stages to reach.

**Name a rule after what it can catch, not what you meant.** The e2e written to
prove "alias, not copy" passed against a deliberately broken build: switching
tabs unmounts the editor, so a value frozen in component state is refreshed on
remount. The model's unit test does catch a real copying implementation. The
claim was wrong, not the code — and only breaking it on purpose showed which.

**A deliberate break can fail for the wrong reason.** Moving a seed role from
0.55 to 0.5 changed nothing on a twenty-shade ramp, because both round to the
same index. The guard was running against one palette. Over five shade counts
it catches the change at 13, 17 and 21.

**Build the check so it cannot be avoided by accident.** The preview page may
use no primitive colour. A scanner reading only `var(--color-primary-500)`
would have missed `className="bg-primary-500"`, which reaches the identical
token without writing `var`. Not malice — just the other way of writing it.

**Push is not merge.** Two documents were pushed to branches and no pull
request was opened, so they sat outside `main` while everything cited them:
the semantic tokens roadmap for all five stages, and the icon guidelines. An
unmerged push is unfinished work, and a plan nobody else can read is not a plan.

**A four-tab bar broke a 375px viewport**, and two existing responsive tests
caught it. At most 900px the strip moves to its own row with
`justify-self: center`, which sizes it to its content — 404px inside 375. Two
patches by guessing found nothing; a probe measuring which element overflowed
found it immediately. Measure before patching layout.

**Dark mode takes three CSS blocks, not two.** `:root` for light, the media
query guarded by `:not([data-theme="light"])`, and `[data-theme="dark"]` last.
Only the media query leaves a theme switch impossible; only the attribute
ignores the system setting until somebody clicks.

**Opacity is not a muted colour.** The preview page faked secondary text with
`opacity-75`, which the colour scanner cannot see and which mixes whatever is
behind the element into the result — so the same text renders differently on a
card than on the canvas. It became `text.secondary`.

**Verify a string replacement matched.** `str.replace` returns the string
unchanged when the pattern is absent, so an edit script can report success
having done nothing. It happened twice: once reported as applied when it was
not, and once when a symbol only existed on another branch. Every replacement
now asserts its match count.
