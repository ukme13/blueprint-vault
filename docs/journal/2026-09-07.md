# Semantic table stage 4b

Stage 4b continues on `feat/semantic-table-b`, from the existing stage 4a
implementation.

## What changed

- Groups now behave like folders: the table shows short names beside the full
  exported variable, and dotted names move a token to the typed folder.
- The All view restores group heading rows. They are sticky inside the table
  scroll region, with 40px above and 8px below.
- New tokens are created in the active folder, or in `custom` from All, and
  open the name cell immediately.
- The row menu now says **Move to group…**, with existing folders and **New
  group** in a submenu.
- Name and description cells support double-click/Enter editing, Escape,
  Enter-to-move-down, Tab-to-move-right, and arrow navigation.
- References remain visible as Figma-style colour chips with a track/weight
  picker. Column separators resize columns, headers reorder columns, and row
  grips reorder siblings without crossing folders.
- Fixed the React key warning and kept drag-and-drop outside `<tbody>` so the
  table remains valid HTML.

## Checks

- `@blueprint/ui`: 814 tests passed.
- Focused semantic Playwright suite: 27 tests passed with one worker.
- Playground type check passed.
- The Stage 4b implementation and follow-up fixes were verified locally before
  this handoff. No broad suite was rerun while preparing the local commits.

## Lessons

The installed seed vocabulary uses load-bearing ids such as
`action.primary`; it does not contain a `primary` folder. The dotted-name
test therefore creates `primary.x` as a custom token. Existing load-bearing
roles still refuse rename, move and delete because consumers read their
exported names directly.
